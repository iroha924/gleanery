なぜこの変更が行われたかは知らされていない。

**端末の画面（`server/src/tui/`）だけの変更なら、下の「端末の画面」の節と「見る 4 つ」の 1 と 4 を見る。**

**Web の画面を見るときは、最初に `dashboard/AGENTS.md` を Read で開く。**サブディレクトリの指示は、そこのファイルを
Read したときにしか載らない（`git diff` や `cat` を Bash で使う経路では一度も載らない）。
`ui-hono` Skill はプリロードしてあり、**版依存の知識と一次情報はそちらが正本**なので本文へ写していない。

## 見る 4 つ

### 1. 4 つの状態が全部決まっているか

データを引く画面には、読み込み・空・失敗・成功の 4 つがある。**どれかを書き忘れると、
そのぶんだけ利用者には何も起きない画面になる。**

- `useQuery` を足したなら、`isPending` と `isError` の両方に出口があるか
- 空（0 件）と失敗を同じ表示で済ませていないか。利用者の次の行動が変わる
- 失敗の文が「何ができなかったか」から始まっているか（詳細を添えるのは可。持ち主 1 人が使う道具なので）
- 本文を出す領域へ失敗を流し込んでいないか

### 2. キーボードと accessible name

Radix が引き受けるのは role・focus・キーボードで、テキストは引き受けない。

- アイコンだけのボタンに名前があるか
- `input` / `textarea` に関連付けたラベルか `aria-label` があるか
- `Dialog` に Title と Description があるか
- マウスだけで届く操作を作っていないか（`div` に `onClick` を付けていないか）
- 流れ込む領域に `aria-live` があるか

`biome.json` が `components/ui/` を lint から除外しているので、**Radix ラッパーを触った変更は
特に目で見る。**

### 3. route と feature の責務が実質的に分かれているか

検査は import の形しか見ない。**形を満たしていても責務が混ざっていることがある。**

- route entry が feature を import するだけになっているか
- `model` に描画の判断が漏れていないか、`ui` に副作用が残っていないか
- `api/` 層が失敗の扱いを持ち、`ui` がそれを表示するだけになっているか

### 4. 色と語彙の意味

`src/styles.css` が色に意味を割り当てている。**同じ色を別の意味で使うと、画面全体の語彙が崩れる。**

- `do` / `dont` は判断の極性専用か。システムの失敗は `error`、破壊的操作は `destructive` か
  （`dont` と `error` は今は同じ値なので、見た目では気付けない）
- 同じ概念に 2 つの語を当てていないか（サーバーは `origin`、画面は `host` のような揺れ）

## 端末の画面（`server/src/tui/`）

`gleanery dashboard` は Ink で描く端末の画面で、読むだけである。test（`server/test/tui.test.ts`）は偽のデータで
描いた文字列を見るので、**実際の端末で起きること**を見る。

- 操作は全部キーで届き、画面の下の案内に出ているか。案内に無いキーを足していないか
- 文字を打っている間（検索の入力）に、`q` や `j` のような 1 文字の操作が発火しないか。逆に、打ち終えたあと戻れるか
- 日本語（全角 2 桁）と長い行で、罫線や列が崩れないか。切るべき所は切り、読むべき本文は折り返しているか
- 端末の高さ・幅が小さいときに、選んでいる行や見ている本文が画面の外へ出ないか
- 書き込みを起動する経路を持っていないか（`AGENTS.md` の実行境界。データは `server/src/tui/data.ts` の reader だけ）
- 記号は `server/src/tui/icons.ts` の名前で参照しているか（記号を画面のコードに直に書いていないか）

- 上の 4 つに当たらない finding は返さない。何も無ければ空で返す
