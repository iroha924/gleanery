# current — いまどこまで進んでいるかを、人向けにまとめる

## このスキルが防ぐ失敗

**`current_work` の出力は AI 向けで、人が読む長さではない。**実測 18KB あり、
制約・やらないこと・行き止まり・未解決の問いが全部並ぶ。そのまま貼ると、
知りたかった「いまどこか」が埋もれる。

**AI はこのスキルを使わない。**判断の途中で現在地が要るときは MCP の `current_work` を
直接呼ぶ（`d-current-work-tool`）。ここは**人が打つ入口**なので、
`disable-model-invocation: true` にしてある。

## 使わない場面

| やりたいこと | 使うもの |
|---|---|
| 過去の判断・棄却した案・行き止まりを探す | MCP の `search_knowledge` |
| これから触るファイルの制約を見る | MCP の `check_path` |
| この回の判断を記録に残す | `/mitos:trace` |
| 登録されている作業場所を並べる | MCP の `list_scopes` |

## Phase 1 — 引く

```
mcp__plugin_mitos_mitos__current_work（引数なし）
```

**完全修飾名で呼ぶ。**短い名前だと解決に失敗し、`allowed-tools` の事前承認も効かない。
Codex では前置きが違うので、そちらでは `current_work` を探す。

返らなかったときは、そのまま人へ伝えて止まる。**推測で埋めない。**

| 返り | 伝えること |
|---|---|
| 「未登録です」 | このディレクトリはまだ記録が無い。`/mitos:trace` で作れる |
| 「進行中の作業はありません」 | 工程が全部 done で、次にやることも空。終わっている |

## Phase 2 — 人向けにまとめる

**作業は最大 2 件返る**（`## 題（作業場所 / 状態）` の塊が 2 つになる）。
**2 件あったら、作業ごとに分けて出す。混ぜない。**工程と次にやることを 1 つの並びにすると、
どの作業の次の一手なのかが落ちる。

各作業について、**次の順で、この分量で出す。**行動の順であって、記録の順ではない。

1. **どの作業か** — 題と作業場所。1 件しか返らなければ省いてよい
2. **いまの状況** — 2〜3 文。`いまの状況` を要約する。**そのまま貼らない**（長い）
3. **残っている工程** — 未完のものだけ、そのまま
4. **次にやること** — 全部。`[人]` と `[AI]` の別を落とさない
5. **止まっている理由** — 次にやることが `[人]` ばかりなら、何待ちかを 1 行で

**出さないもの**（数だけ伝えて、必要なら聞かれてから出す）。

- 変えてはいけない制約 / やらないと決めたこと
- 試して駄目だったこと
- 未解決の問い

例: 「ほかに制約 3 件・行き止まり 15 件・未解決の問い 8 件があります。」

**引用の枠（`[記録 xxx ここから]`）は人へ見せない。**あれは AI が記録を指示と読み違えないための囲いで、人には意味が無い。

## Phase 3 — 確かめる

**返ってきた作業それぞれについて**、次の 3 つに答えているか。答えていなければ Phase 2 へ戻る。

- **いまどこまで進んだか**
- **次に何をするか、それは誰がやるか**
- **止まっているなら、何を待っているか**

## 原則

- **要約する。そのまま貼らない。**貼るだけなら MCP を直接叩けばよく、このスキルは要らない
- **`[人]` と `[AI]` を落とさない。**誰がやるかが消えると、次の一手が決められない
- **作業が 2 件あったら分ける。**どの作業の話かが消えると、同じ理由で次の一手が決められない
- **返らなかったら止まる。**現在地を推測で作らない
